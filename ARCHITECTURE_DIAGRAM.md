## 点云配准详细流程

```
┌─────────────────────────────────────────────────────────────────┐
│                   点云配准与变换流程（关键步骤）                    │
└─────────────────────────────────────────────────────────────────┘

步骤1: 加载位姿文件
┌─────────────────────────────────────────────────────────┐
│  poses.txt (来源: LiDAR里程计) ⭐⭐⭐                     │
│  ├─ SemanticKITTI: KITTI Odometry Dataset               │
│  │   └─ 基于LiDAR扫描配准的里程计算法                    │
│  └─ nuScenes: ego_pose (多传感器融合，以LiDAR为主)      │
│                                                          │
│  格式: 4x4位姿变换矩阵                                   │
│  ┌                    ┐                                  │
│  │ R11  R12  R13  tx │  T_w_cam0 (相机坐标系下的位姿)  │
│  │ R21  R22  R23  ty │                                  │
│  │ R31  R32  R33  tz │                                  │
│  │  0    0    0   1  │                                  │
│  └                    ┘                                  │
└─────────────────────────────────────────────────────────┘
                    ↓
步骤2: 坐标系转换
┌─────────────────────────────────────────────────────────┐
│  读取标定文件 calib.txt                                  │
│  ├─ T_cam_velo: 相机到LiDAR的变换矩阵                   │
│  └─ T_velo_cam: LiDAR到相机的变换矩阵 (逆矩阵)          │
│                                                          │
│  转换位姿到LiDAR坐标系:                                  │
│  T_velo = T_velo_cam @ inv(T_0) @ T_cam @ T_cam_velo   │
│                                                          │
│  其中:                                                   │
│  - T_0: 第一帧的位姿（用于相对位姿计算）                 │
│  - T_cam: 当前帧在相机坐标系下的位姿                     │
│  - T_velo: 转换后的LiDAR坐标系位姿                      │
└─────────────────────────────────────────────────────────┘
                    ↓
步骤3: 加载多帧点云
┌─────────────────────────────────────────────────────────┐
│  时间序列点云:                                           │
│  ├─ 帧 t-n:  P_{t-n} = {(x, y, z, intensity)_i}        │
│  ├─ 帧 t-n+1: P_{t-n+1}                                │
│  ├─ ...                                                 │
│  └─ 帧 t:    P_t (当前帧)                              │
│                                                          │
│  配置参数:                                               │
│  - N_PAST_STEPS = 2 (使用当前帧 + 1个历史帧)           │
│  - DELTA_T_PREDICTION = 0.1s (时间间隔)                │
└─────────────────────────────────────────────────────────┘
                    ↓
步骤4: 点云配准变换
┌─────────────────────────────────────────────────────────┐
│  将历史帧点云变换到当前帧坐标系:                          │
│                                                          │
│  对于每个历史帧 i:                                       │
│    from_pose = T_velo[i]     # 历史帧位姿               │
│    to_pose = T_velo[current]  # 当前帧位姿              │
│                                                          │
│    # 计算相对变换矩阵                                    │
│    T_relative = inv(to_pose) @ from_pose                │
│                                                          │
│    # 应用变换到点云                                      │
│    P_i_homogeneous = [P_i, ones]  # 齐次坐标            │
│    P_i_transformed = (T_relative @ P_i_homogeneous.T).T│
│                                                          │
│  结果: 所有历史帧点云都配准到当前帧坐标系                 │
└─────────────────────────────────────────────────────────┘
                    ↓
步骤5: BEV残差图像生成
┌─────────────────────────────────────────────────────────┐
│  将配准后的点云投影到BEV (Bird's Eye View):             │
│                                                          │
│  1. 当前帧BEV图像:                                       │
│     BEV_current = project_to_BEV(P_current)             │
│                                                          │
│  2. 历史帧BEV图像 (已配准):                              │
│     BEV_history = project_to_BEV(P_history_transformed) │
│                                                          │
│  3. 计算BEV残差:                                         │
│     BEV_residual = BEV_current - BEV_history            │
│                                                          │
│  4. 编码运动特征:                                        │
│     motion_features = encode(BEV_residual)              │
│                                                          │
│  网格参数:                                               │
│  - 范围: [-60, -50, -4] to [60, 50, 2] (m)            │
│  - 网格大小: 0.1m × 0.1m                                │
│  - BEV图像尺寸: 1200×1000                               │
└─────────────────────────────────────────────────────────┘
                    ↓
步骤6: 特征融合
┌─────────────────────────────────────────────────────────┐
│  融合点云特征与运动特征:                                  │
│                                                          │
│  点云特征: [x, y, z, intensity] (4维)                   │
│  运动特征: [motion_1, motion_2, ...] (n-1维)           │
│                                                          │
│  融合后特征: [x, y, z, intensity, motion_features]      │
│               └───── 空间特征 ─────┘  └─ 运动特征 ─┘    │
│                                                          │
│  维度: 4 + (N_PAST_STEPS - 1) = 4 + 1 = 5维            │
└─────────────────────────────────────────────────────────┘
```

## 为什么使用LiDAR里程计而非IMU？

```
┌─────────────────────────────────────────────────────────┐
│              LiDAR里程计 vs IMU对比分析                   │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  LiDAR里程计 (项目实际使用) ✓                            │
│  ├─ 输出格式: 4×4位姿变换矩阵 (直接可用)                 │
│  ├─ 精度: 高精度 (通过扫描配准)                          │
│  ├─ 累积误差: 相对较小                                   │
│  ├─ 适用场景: 室外大范围环境                             │
│  └─ 数据来源:                                            │
│      • SemanticKITTI: KITTI Odometry poses.txt          │
│      • nuScenes: ego_pose (融合多传感器)                │
│                                                          │
│  IMU (未使用) ✗                                          │
│  ├─ 输出格式: 角速度+加速度 (需要积分)                   │
│  ├─ 精度: 短期高精度，长期漂移大                         │
│  ├─ 累积误差: 积分误差随时间累积                         │
│  ├─ 适用场景: 短时间运动估计                             │
│  └─ 局限性:                                              │
│      • 需要复杂的积分和滤波算法                          │
│      • 无法直接提供全局一致的位姿                        │
│      • 项目数据集未提供原始IMU数据                       │
│                                                          │
│  项目为何选择LiDAR里程计?                                │
│  1. 数据集提供的是LiDAR里程计结果（poses.txt）           │
│  2. 无需额外处理，直接使用变换矩阵                       │
│  3. 全局一致性好，适合多帧配准                           │
│  4. 精度满足4D语义分割任务需求                           │
└─────────────────────────────────────────────────────────┘
```

## 训练与推理时间线

```
时间线 (T代表时间步长 = 0.1秒)

T=0         T=1         T=2         T=3         T=4
 │           │           │           │           │
 ├─ Frame 0  ├─ Frame 1  ├─ Frame 2  ├─ Frame 3  ├─ Frame 4
 │           │           │           │           │
 │           │           │           │           │
 └───────────┴───────────┘           │           │
      配准到Frame 2坐标系              │           │
         (历史帧)                     │           │
                                     │           │
                          当前帧 ────▶ │           │
                        (预测目标)    │           │
                                     │           │
                          └───────────┴───────────┘
                               配准到Frame 4坐标系
                                  (下一批次)

数据流:
Frame 0, 1 → 配准到Frame 2 → 生成BEV残差 → 运动特征 → 预测Frame 2
Frame 1, 2 → 配准到Frame 3 → 生成BEV残差 → 运动特征 → 预测Frame 3
Frame 2, 3 → 配准到Frame 4 → 生成BEV残差 → 运动特征 → 预测Frame 4
...
```
